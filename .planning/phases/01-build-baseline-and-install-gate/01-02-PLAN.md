<objective>
Vendor `CydiaSubstrate.framework` into the repo once, and write `bramble/bootstrap-toolchain.sh`
— the script that turns a bare machine (no `$THEOS`, no `~/theos`, GNU make 3.81) into one with
Theos, the iOS SDK, theos-jailed, and YouTubeHeader installed under a repo-local, gitignored
directory, all pinned to the commit SHAs Plan 01-01 recorded in `bramble.config.example`.

Purpose: D-05 requires "one command means one command on a bare machine" — this script is that
bootstrap step, invoked by Plan 01-03's packaging script whenever `$THEOS` is missing. D-06 requires
the toolchain be self-contained per-repo (no surgery on a shared machine-global `~/theos`). D-07
requires deterministic SHA pins, not `master`. D-08 requires the build never contact
`apt.saurik.com` at any point after this plan runs once.
Output: `bramble/bootstrap-toolchain.sh`, `bramble/vendor/CydiaSubstrate.framework/` (committed
binary).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Toolchain bootstrap (this script) | Fetches and executes code from GitHub (Theos, theos-jailed, YouTubeHeader) — a supply-chain boundary crossed once per bare machine |
| Vendored CydiaSubstrate.framework | Third-party binary from an unmaintained, HTTP-only host, committed once and trusted thereafter |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-03 | Tampering | Theos / theos-jailed / YouTubeHeader clones | mitigate | Pinned to SHAs from `bramble.config` (D-07); script asserts `git rev-parse HEAD` equals the pin after checkout and fails loudly otherwise, so a compromised `master` branch cannot silently substitute code |
| T-01-04 | Tampering | CydiaSubstrate.framework fetched over plain HTTP from apt.saurik.com | mitigate | Fetched exactly once, by this plan, with the download's SHA-256 recorded in `bramble/vendor/CydiaSubstrate.framework.sha256-provenance.txt`; every subsequent build reuses the committed, reviewable binary and never touches the network for it again (D-08) |
| T-01-05 | Denial of Service | Bootstrap re-run on every invocation re-downloading multi-hundred-MB SDK/toolchain | mitigate | Idempotency checks (`if not exists`) before every clone/download step, verified in acceptance criteria's second-run timing assertion |
</threat_model>
