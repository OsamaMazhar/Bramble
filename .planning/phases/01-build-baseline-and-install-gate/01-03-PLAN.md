<objective>
Write `bramble/package.sh` — the single script an operator runs to turn a config-supplied input
IPA into a verified, correctly-named unsigned IPA. This is PKG-01's "in one invocation" deliverable:
it resolves the input (local path or cached URL fetch), rejects a non-stock input, reads the real
YouTube version and deployment target from it, drives `make package` (bootstrapping the toolchain
first if needed), then hard-fails the build if any of D-09's four checks — plus a fifth,
D-14-derived check on the compiled dylib itself — do not pass, emitting a build manifest only on
success.

Purpose: this is the phase's core deliverable — everything upstream (Makefile, Tweak.x, toolchain
bootstrap) exists to be driven by this one script, and everything downstream (the synthetic
version-bump proof, the device install gate) depends on the IPA it produces.
Output: `bramble/package.sh`, and — once the operator's `bramble.config` carries a real
`INPUT_IPA_SOURCE` — a real unsigned IPA under `bramble/build/`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| Operator-supplied input IPA | An untrusted binary of unverified provenance crossing into the build pipeline |
| build-manifest output | A committed-adjacent artifact that must never carry `INPUT_IPA_SOURCE` (may hold credentials/tokens if URL-sourced) |
| Compiled Bramble.dylib | The artifact D-14's INERT=1 claim rests on — must be verified directly, not inferred from source text |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-06 | Tampering | Operator-supplied input IPA already carrying an injected dylib or foreign bundle | mitigate | D-11 stock-input check in Task 1, run before any build work, names the offending path in its failure message |
| T-01-07 | Information Disclosure | `INPUT_IPA_SOURCE` (may be a credentialed URL) leaking into the manifest or console output | mitigate | Task 2's manifest write explicitly excludes `INPUT_IPA_SOURCE`; acceptance criteria include a manual review pass over every reference to the variable, plus an automated `<verify>` check that greps every produced `bramble/build/build-manifest-*.txt` for the configured `INPUT_IPA_SOURCE` value and fails if found, once a real config and manifest exist |
| T-01-08 | Denial of Service | A malformed or oversized input exhausting disk during unzip | accept | Single-operator private tool, ASVS L1; not worth pre-flight disk-space engineering for this audience |
| T-01-09 | Tampering | A build that fails a D-09 check but still leaves a partially-built IPA on disk | mitigate | Task 2 explicitly deletes `$OUTPUT_IPA` on any check failure before exiting |
| T-01-14 | Tampering | An `INERT=1` dylib silently retaining hook-registration code despite the source-level `#ifndef BRAMBLE_INERT` guard (Plan 01-01 Task 2), which only proves guard *placement* in source, not what the compiler actually emitted | mitigate | Task 2's Check 5 asserts the `MSHookMessageEx` symbol count is exactly 0 on an inert build and greater than 0 on a live build, verifying the compiled artifact directly rather than trusting source-text placement |
