## Phase Goal

**As a** developer running Bramble's packaging pipeline, **I want to** turn a config-supplied,
decrypted YouTube IPA into an installed build via one command, **so that** I can confirm on a real
device — before any hook or ad-blocking logic is written — that the dylib loads and a real Google
account still signs in.

> Adaptation note: ROADMAP.md's Phase 1 `**Goal:**` line ("The tweak reaches a real device, and the
> account it needs still works") is outcome-shaped, not literally in `**As a**/**I want to**/**so
> that**` form. This restates it in that shape using only already-decided content (PROJECT.md's
> core value, ROADMAP's Phase 1 goal and Gate note, CONTEXT.md's decisions) — no new scope is
> introduced. Flagged here per MVP-mode's "do not invent a story" rule rather than silently
> reshaping it.

<objective>
Retarget `bramble/Makefile` from upstream YouTube-X's jailbreak `.deb` build to `MODULES = jailed`
packaging, add the `%ctor` load-line + `INERT=1` support to `bramble/Tweak.x`, and define the
single config-file contract (`bramble.config.example`) every later script in this phase reads from.

This plan defines contracts (Makefile variables, config keys, the `BRAMBLE_INERT` compile flag)
that Plan 01-02 (toolchain bootstrap) and Plan 01-03 (packaging script) consume. No tweak
*behavior* changes — every existing `%hook` body is moved, not edited.

Purpose: prove the packaging target shape and the load-line/inert mechanisms compile-clean before
any script drives them, per D-01, D-02, D-03, D-06 (partial), D-09 (partial), D-10 (partial),
D-13, D-14.
Output: retargeted `bramble/Makefile`, `%ctor`-equipped `bramble/Tweak.x`, `bramble.config.example`,
updated `.gitignore`, `bramble/control` and `bramble/YouTubeX.plist` removed (no consumer in the
jailed pipeline).
</objective>
